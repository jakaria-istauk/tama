Features

Everything a team board needs, all included

Simple enough to start in a minute, with the depth real projects need. No paid tiers, no locked views.

Five board views

Kanban, grid, list, calendar and timeline. Pick one as each board's default.

Timeline and start dates NEW

Give cards a start date and see them as bars from start to due date. Drag to reschedule.

Automation rules

"When this happens, do that" rules per board: move, label, assign, set due dates or comment.

Recurring cards and templates

Save cards as templates with labels and tasks ready, and create them daily, weekly or monthly.

Saved filters

Filter by member, label, creator or due date, save it, and get back to it in one click.

Rich cards

Markdown, attachments, comments, tasks, labels, custom fields, due dates and a stopwatch.

Real-time collaboration

Every change shows up for everyone at once, with comments and activity together in one feed.

Notifications, webhooks, API

Send updates to 100+ services through Apprise, or build on webhooks and a documented REST API.

Secure and private

Google sign-in, two-factor authentication, personal API keys and roles from admin to viewer.

New · Timeline view

See the whole plan, from start to finish

Cards now have a start date as well as a due date. The timeline draws each card as a bar across the days it runs, one row per list, so overlaps and gaps stand out at a glance.

  • Drag a bar to move it, or drag its ends to change the dates.
  • Cards without dates wait in a tray. Drop one on a day to schedule it.
  • Moving a due date on the calendar moves the start date along with it.
  • Set the timeline as a board's default view.

Automation

Let the board do the busywork

Write rules in plain terms: when a card is created or moved, gets a label, passes its due date or has every task done, run up to ten actions. Every change a rule makes shows in the card's activity, with the rule's name.

  • Move cards, add or remove labels and members, set or complete due dates, post comments.
  • Recurring cards from templates: every day, on chosen weekdays, or monthly on a day.
  • Turn rules on and off without deleting them.

AI assistants

Your AI assistant, on your board

Tama has a built-in Model Context Protocol server. Connect an assistant and ask it to plan a sprint, sort a backlog, set up a rule or write up a card. It works as you, so it sees and changes only what you can.

  • Claude and ChatGPT connect through OAuth, with a consent screen.
  • Coding agents connect with a personal API key.
  • See and disconnect connected apps at any time.
Claude ChatGPT Claude Code Codex Cursor VS Code Gemini CLI Windsurf 
# Connect Claude Code to your Tama
claude mcp add --transport http tama \
  https://tama.example.com/api/mcp \
  --header "X-Api-Key: <api key>"

Why Tama

Why Tama instead of a hosted board?

Trello, Asana and similar tools are good boards. Tama gives you the same way of working, on terms you control.

Tama Typical hosted board
Where your data lives On your own server On the vendor's cloud
Price Free, no per-user fees Paid per user for the full feature set
Boards, cards and members No limits beyond your server Free plans cap boards or collaborators
Views Kanban, grid, list, calendar and timeline, all included Timeline and calendar often on paid plans
Automation Rules, recurring cards and templates with no run limits Monthly run quotas, more on paid plans
AI assistants Built-in MCP server; bring Claude, ChatGPT, Cursor and more Usually the vendor's own AI, often a paid add-on
Source code Public: read it, fork it, change it Closed

Plans and limits of hosted tools vary and change over time; check each vendor's pricing page.

Fine-grained access

Admins, project owners, board editors and read-only viewers, each with the rights they need.

Get started

Running in a few minutes

All you need is a server with Docker and Compose.

Get the code

Clone the repository.

git clone https://github.com/jakaria-istauk/tama.git
cd tama

Configure

In docker-compose.yml, set BASE_URL and a random SECRET_KEY.

openssl rand -hex 32

Start it

Start Tama and create the first admin.

docker compose up -d --build
docker compose run --rm tama \
  npm run db:create-admin-user

More ways to deploy: Kubernetes, Cloudflare Tunnel
